Certificate decoder and chain checker

Paste a certificate, a chain or a CSR as PEM, or the DER as base64 or hex. Several certificates are checked as a chain: each one against the next, and if the order is wrong, the right order. Add a key to check it belongs to the certificate.

{{template "cipher/engine" .}}

Read in this tab, never uploaded; a picked file is read instead of the text. (With JavaScript off it is uploaded with the form.)

A public key answers the match as well as the private one does: openssl pkey -in key.pem -pubout prints it.

Using this from the terminal

Every tool here also answers a plain POST with JSON. From a terminal your input goes to this server, unlike on the page, which runs everything in your browser.

curl {{.Base}}/cert --data-urlencode cert@fullchain.pem
  curl {{.Base}}/cert --data-urlencode cert@cert.pem --data-urlencode key@public.pem

POST only. Fields: cert (or a cert_file upload), optional key, and now (unix seconds) to check validity at another moment. The API runs on this server, so what you send travels: match with the public key, never the private one. This page doesn't send anything anywhere.

The same with openssl

openssl x509 -in cert.pem -noout -text                  # read a certificate
openssl req -in csr.pem -noout -text                    # read a CSR
openssl x509 -in cert.pem -noout -fingerprint -sha256   # fingerprint over the DER
openssl x509 -inform DER -in cert.der -out cert.pem     # DER to PEM
openssl verify -CAfile root.pem -untrusted intermediate.pem cert.pem   # check a chain
openssl x509 -in cert.pem -noout -pubkey | openssl sha256   # key match: these two
openssl pkey -in key.pem -pubout | openssl sha256           # lines print the same
