What that means in practice

This catalog is hand-maintained from vendor documentation and it is deliberately conservative, because a wrong deletion is worse than a missed one: a removed parameter that turned out to be functional breaks the page you were trying to reach, silently, and you have no way of knowing that is what happened.

  • Ambiguous names are scoped to a host or they are absent. ref is a tracker on some sites and a git branch on others, and nothing in the name separates the two.
  • Some known trackers are deliberately left in. Amazon's th and psc choose which product variant renders; Substack's publication_id and post_id read as record IDs; the Shopify group is identifiable only by host, and a Shopify storefront is an arbitrary custom domain. Wrong product beats a clean URL.
  • It does not guess from the shape of a name. Every rule names its parameter exactly, so a URL that comes back unchanged has been checked against these rules, not certified clean.

* at the end of a name matches every parameter that starts with it: utm_* covers utm_source, utm_medium and the rest. A host ending in a dot, like amazon., covers every country domain: amazon.com, amazon.co.uk, amazon.de. unsourced means no vendor documentation was found and the rule rests on observed behaviour. A wrapper's confidence says how settled its format is: a medium one may change without notice.

Wrappers that get unwrapped

Mail gateways and link shims that carry the real destination inside the link itself. Every one of these is read out of the URL text. Nothing is fetched, so the gateway never learns you looked, and a wrapper whose target is a server-side token cannot be recovered here at all — that is stated rather than guessed at.
