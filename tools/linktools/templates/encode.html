Why a query and a path encode differently

A query string inherits application/x-www-form-urlencoded from HTML forms, where a space is written +. A path never did, so there a space is %20 and + is an ordinary character. /a+b/ is a directory literally called a+b.

This bites hardest with base64, where + is part of the alphabet: a decoder that applies form rules to a base64 value destroys it silently. The reference page has the worked example.

The value is converted on this server and nothing is fetched. It does travel here like any other input, so the usual rule holds: don't paste a live token into a web tool, this one included.

Using this from the terminal 
curl '{{.Base}}/encode?v=a%20b'

Both lists come back as ordered arrays carrying the note and, where one failed, the reason it failed.
